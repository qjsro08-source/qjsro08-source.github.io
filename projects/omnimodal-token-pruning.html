방법Method

중요한 토큰과 대체되지 않는 토큰을 남긴다Keep tokens that matter and cannot be replaced

오디오와 비디오를 함께 받는 옴니모달 LLM은 입력 토큰이 크게 불어나 연산과 메모리를 많이 씁니다. 기존 프루닝은 토큰 하나가 받는 어텐션이나 두 토큰 사이의 유사도를 봅니다. 이 프로젝트는 어텐션으로 본 중요도에 질문 하나를 더합니다 — 이 토큰이 이번 레이어에서 새로 얻은 정보를, 다른 토큰들의 조합으로 설명할 수 있는가?Omni-modal LLMs that take audio and video together face a flood of input tokens, which costs compute and memory. Existing pruning looks at the attention a single token receives or the similarity between two tokens. This project adds one question to attention-based importance: can the information this token gained in this layer be explained by a combination of other tokens?

각 레이어에서 attention과 FFN이 토큰에 더하는 업데이트 Δ를 모듈 입력 방향에 평행한 성분과 직교하는 성분으로 나누고, 직교 업데이트만 떼어냅니다. 그다음 이 업데이트를 후보 토큰들의 직교 업데이트로 ridge regression 복원합니다. 복원 오차가 크다는 것은 그 토큰이 이웃에게서 얻을 수 없는 정보를 새로 가져왔다는 뜻입니다. 이 복원 오차를 어텐션 점수와 합쳐, 중요하면서 대체되지 않는 토큰을 남깁니다.At each layer we split the update Δ that attention and the FFN add to a token into a component parallel to the module's input direction and one orthogonal to it, and keep only the orthogonal update. We then reconstruct this update from the candidate tokens' orthogonal updates with ridge regression. A large reconstruction error means the token brought in information its neighbors cannot supply. Combining this error with attention scores, we keep tokens that are important and not replaceable.

Stage 1 · Pre-LLM

모달리티 안에서 복원Reconstruct within a modality

비디오 토큰은 같은 프레임의 3×3 공간 이웃으로, 오디오 토큰은 앞뒤 시간 이웃으로 직교 업데이트를 복원합니다. attention과 FFN의 복원 오차를 인코더 레이어에 걸쳐 누적해 점수를 만듭니다.Video tokens reconstruct their orthogonal updates from their 3×3 spatial neighbors in the same frame, audio tokens from their temporal neighbors on either side. Reconstruction errors of attention and FFN accumulate across encoder layers into a score.

이 점수를 인코더 어텐션과 순위 정규화로 합친 뒤(S = wR(a) + (1−w)R(s)), LLM에 들어가기 직전에 시간 청크마다 상위 토큰만 한 번에 남깁니다.This score is combined with encoder attention by rank normalization (S = wR(a) + (1−w)R(s)), and right before the LLM only the top tokens of each time chunk are kept, in a single pass.

Stage 2 · Inner-LLM

오디오로 비디오를 복원Reconstruct video from audio

LLM 안에서는 오디오와 비디오가 정렬되기 시작합니다. 각 비디오 토큰의 평균 중심화한 업데이트를 같은 시간 청크의 오디오 토큰으로 복원하고, 상대 복원 오차를 레이어마다 누적합니다.Inside the LLM, audio and video begin to align. Each video token's mean-centered update is reconstructed from the audio tokens of the same time chunk, and the relative reconstruction error accumulates layer by layer.

여기에 마지막 프롬프트 토큰의 어텐션(질문과의 관련성)을 합쳐, 여러 LLM 레이어에 걸쳐 비디오 토큰을 점진적으로 줄입니다. 오디오 토큰은 유지합니다.Combined with the attention of the last prompt token (its relevance to the question), this prunes video tokens progressively across several LLM layers. Audio tokens are kept.

관찰Observations

설계를 이끈 두 가지 관찰Two observations behind the design

OBSERVATION 01

레이어가 더하는 변화는 대부분 직교 성분이다Most of what a layer adds is orthogonal

누적된 token state만 보면 이웃 토큰끼리 무척 비슷합니다(이웃 cosine 유사도 평균 비전 0.620, 오디오 0.893). 그러나 블록이 더하는 업데이트로 보면 훨씬 덜 닮았습니다(0.385, 0.601). 같은 상태에서 출발한 토큰도 레이어마다 다른 변화를 겪는다는 뜻입니다.Looking only at accumulated token states, neighboring tokens are very similar (mean neighbor cosine similarity 0.620 for vision, 0.893 for audio). Looking at the updates each block adds, they are far less alike (0.385, 0.601): tokens that start from the same state still change differently in each layer.

그 업데이트를 입력 방향에 대해 분해하면, 오디오 인코더에서 직교 성분이 업데이트 에너지의 평균 88% 이상을 차지하고 비전 인코더도 비슷합니다. 직교 성분을 평행 성분 크기만큼 줄이면 평행 성분을 통째로 지울 때보다 정확도가 더 떨어집니다. 토큰이 새로 얻는 정보는 직교 성분에 실려 있고, 그래서 직교 업데이트를 복원 대상으로 삼습니다.Decomposing those updates against the input direction, the orthogonal component carries over 88% of update energy on average in the audio encoder, and the vision encoder is similar. Shrinking the orthogonal component to the size of the parallel one costs more accuracy than deleting the parallel component outright. New information lives in the orthogonal component, so the orthogonal update is what we reconstruct.

OBSERVATION 02

모달리티 사이의 유사성은 단계마다 다르다Cross-modal similarity differs by stage

Pre-LLM 단계에서는 오디오와 비디오 인코더가 따로 돌기 때문에, 두 모달리티 평균 token state의 cosine 유사도가 32개 인코더 레이어 내내 0 근처에 머뭅니다. 반면 LLM 안으로 들어가면 레이어가 깊어질수록 0.2 수준에서 0.9 이상까지 올라갑니다. 두 모달리티가 LLM 안에서 정보를 공유하기 시작한다는 뜻입니다.At the Pre-LLM stage the audio and video encoders run separately, so the cosine similarity of the two modalities' mean token states stays near 0 across all 32 encoder layers. Inside the LLM it rises with depth, from about 0.2 to above 0.9: the two modalities begin to share information in the LLM.

실제로 비디오 청크의 직교 업데이트를 오디오 청크로 복원해 보면, 깊은 레이어에서 같은 시간 위치의 오디오가 가장 잘 설명하는 대각선 패턴이 뚜렷해집니다. 그래서 Pre-LLM에서는 같은 모달리티 안의 이웃으로, Inner-LLM에서는 같은 시간 구간의 오디오로 비디오를 복원합니다.Reconstructing video chunks' orthogonal updates from audio chunks, deep layers show a clear diagonal pattern in which audio at the same time position explains best. So Pre-LLM reconstructs from neighbors within the same modality, and Inner-LLM reconstructs video from audio in the same time window.

결과Results

같은 토큰 예산에서 가장 높은 정확도Highest accuracy at the same token budget

Qwen2.5-Omni-7B에서 토큰을 45%만 남기면 AVUTBench 64.2(DASH 63.5), ShortVid-Bench 70.3(69.9)으로 Full 대비 성능 99.9%를 유지합니다. 35%까지 줄여도 99.3%입니다. WorldSense에서는 45%·35%에서 46.7·46.5로 OmniZip(45.9·45.3)과 DASH(45.9·45.6)를 모두 넘습니다.On Qwen2.5-Omni-7B, keeping 45% of tokens gives AVUTBench 64.2 (DASH 63.5) and ShortVid-Bench 70.3 (69.9), retaining 99.9% of Full performance; at 35% it is still 99.3%. On WorldSense, 46.7 and 46.5 at 45% and 35% beat both OmniZip (45.9, 45.3) and DASH (45.9, 45.6).
