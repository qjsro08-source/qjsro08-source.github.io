38턴 전체로는 API 4종이 $0.0176–$0.3507, Ours는 $0입니다.

Gemma 4 E4B에 육아 서적으로 LoRA를 학습하고 Q4_0으로 양자화해 기기 안에서 돌린 답변입니다(턴마다 일부 문장만 발췌). 문장마다 아이 기록이나 전문자료 근거가 붙고, 판단에 필요한 정보가 없으면 그렇다고 표시합니다. 비용은 같은 대화를 API 모델로 돌렸을 때의 실측값입니다.

  • $0답변 생성 비용 — 38턴, API는 $0.0176–$0.3507
  • 51 tok/s온디바이스 생성 속도 (중앙값)
  • Q4_04-bit 양자화로 기기 안에서 실행
  • 5 × 38같은 대화를 모델 5개로 비교

구조

답변은 기기 안에서 만든다

육아 상담은 수유·배변·발열 같은 아이의 민감한 기록을 그대로 다루고, 부모는 같은 상황을 하루에도 몇 번씩 되묻습니다. 그래서 답변 모델을 기기 안에서 돌리는 작은 LLM으로 두었습니다. 아이 기록이 담긴 근거를 외부 모델에 보내지 않고 답을 만들며, 질문이 늘어도 비용이 늘지 않습니다.

질문이 들어오면 먼저 어떤 경로가 필요한지 분류하고, 필요하면 아이 기록과 전문자료를 찾아 답에 쓸 근거만 압축합니다. 답변 모델은 이 근거를 받아 정해진 네 부분으로 답하고, 문장마다 근거 ID를 답니다. 근거가 없는 판단은 하지 않고 정보 부족으로 표시한 뒤 되묻습니다.

  1. 1질문 분류단순 응답 · 기록 조회 · 전문자료 · 위험 대응
  2. 2근거 찾기아이 기록 208건 · 전문자료 5종 467청크
  3. 3근거 압축답에 쓸 문장만 남기고 ID를 붙임

차이가 답변 모델에서만 나오도록

같은 대화 10세트 38턴을 모델 5개로 돌렸습니다. 질문 분류·기록 조회·전문자료 검색·근거 압축은 GPT-5.6 Luna로 한 번만 실행해 고정하고 모든 모델에 똑같이 넣었으며, 이전 턴의 답변도 고정 대본으로 두어 모든 모델이 같은 대화 이력을 봅니다. 그래서 결과의 차이는 답변 모델에서 나옵니다. 아이는 10개월, 기록은 208건, 전문자료는 5종 467청크입니다.

#유형세트보는 것첫 발화
01단순 대화인사와 격려과잉 대응하지 않고 사람처럼 답하는가“안녕하세요, 오늘 처음 써 봐요”
02기록 조회밤잠 기록 파고들기‘그중에’, ‘낮잠은?’처럼 앞 턴에 기대는 후속 질문“지난 이주일 밤잠 기록 좀 보여줘”
03기록 조회성장 기록‘키는?’처럼 극단적으로 짧은 후속 질문“우리 아이 몸무게 기록 알려줘”
04전문자료 검색이유식 진행전문자료 근거를 대야 하는 질문이 연달아 올 때“10개월인데 이유식을 하루 몇 번 주는 게 맞을까요”
05전문자료 검색수면교육 상담부모가 표현한 거부감을 다음 답에 반영하는가“밤에 자꾸 깨는데 수면교육 시작해도 될까요”
06의학 지식 · 위험발열 경과실제 발열·투약 기록과 이어지는 위험 판단과 병원 권고“아침에 열이 38.2도였는데 지금은 37.9도예요”
07의학 지식 · 위험호흡 이상응급 판단을 미루거나 과하게 놀래키지 않는가“쌕쌕거리는 소리도 조금 나요”
08기록 + 지식수유량 적정성기록 조회에서 일반 지식으로 경로가 바뀌는 대화“어제 분유 몇 번 먹었는지 기록 보여줘”
09의학 지식 · 위험해열제 중복투여부모를 탓하지 않으면서 위험을 정확히 전달하는가“해열제를 두 번 준 것 같아요. 8시랑 9시에요”
10맥락 의존구토 맥락의존‘두 번이요’, ‘그건’처럼 앞 턴 없이는 해석할 수 없는 발화“어제 아기가 토했어요”

같은 형식의 답을, 비용 없이

API 모델 4종은 같은 38턴에 $0.0176–$0.3507을 썼고, 기기 안에서 도는 Ours는 비용이 들지 않습니다. 답변은 모두 관찰된 사실 · 일반 설명 · 권장 행동 · 되묻기의 같은 형식으로 나오며, Ours는 문장마다 아이 기록과 전문자료 근거 ID를 붙입니다. 생성 속도는 온디바이스 기준 초당 51토큰(중앙값)입니다.
